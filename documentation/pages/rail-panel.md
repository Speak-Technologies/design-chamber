# Rail panel

**Route:** the Design Chamber icon in OpenChamber's rail · **Access:** every OpenChamber user; nothing to sign in to
**Purpose:** The navigator. Browse the designs your chat agent has written, open one in a compact viewer, and change settings — all inside the 320–480 px rail. (The full wall, with room to work, is the [full-screen page](full-screen-page.md).)

Screenshots are taken in the OpenChamber dark and light themes at 320 px and 480 px (`documentation/pages/img/rail-<width>-<theme>-*.png`, generated by `test/ui/visual/shoot.mjs` — the real UI and guest core with the local service replaced by the in-memory fake in `test/ui/visual/`).

## Behaviour by role
There is one role: the OpenChamber user. Chat links (a design chip, "Open as page") open the viewer here, and so will a Work Status row or a chat block: they leave an open request with an intent, `view` (the default) or `comment`. A `comment` request opens the design in Edit with **Comment** pressed, so the next click pins a comment; if that design is already open here it switches to Edit. An open request wins over the design the rail would otherwise reopen (see "Keeps your place" below). While the rail is open it also delivers a revision the full-screen page handed over for a chat that wasn't selected, once that chat is selected, and saves a version after each agent turn.

## Data
**Reads:** the designs list, one design's detail, versions, settings, presets and thumbnails — all through the guest store (`GET /designs`, `/designs/:slug`, `/versions`, `/settings`, `/presets`, `/thumbnail`, `/render`).
**Writes (through the service):** rename (`PATCH /designs/:slug`), delete (`DELETE`, moves to `.trash`), comments (create / edit / resolve / delete / mark sent), version snapshot and restore, export, reveal, settings, loose-file import (`POST /loose/import`).
**Stored in `host.storage`:** `loose-dismissed` (the file names you said Not now to), `tip:full-screen`, `view:<slug>` (per-design view settings) and `place:panel` (the open design, below).

## Keeps your place
OpenChamber reloads the rail's frame whenever the extension updates (a folder edit, a rebuild, a Git update), and the rail used to start on the list each time, so a few minutes in you could be sent back out of the design you were looking at. Now the rail remembers the open design: opening one stores its slug in `host.storage` under `place:panel` (instance scope), and going back to the list clears it. When the frame starts it reads that value once, waits for the designs list, and reopens the design if it is still there (its camera, hidden sizes and page view come back from `view:<slug>`). Three cases:
- **The design is gone** (deleted or moved): the rail shows the list, says nothing, and forgets the place.
- **An open request is waiting** (Work Status, a chat block, "Open as page"), or you open a design before the rail has finished starting: that one wins and is the one remembered.
- **Nothing remembered, or something unreadable in storage:** the list, as before.
It remembers the design only, not a drawer, a sheet or the New dialog. The [full-screen page](full-screen-page.md) does the same under its own key, `place:page`, so a design opened in the rail never reopens in the page. Pure decision: `src/ui/model/place-model.ts`; wiring: `src/ui/components/place-memory.ts`.

## States & edge cases
- **Loading:** skeleton rows in the list, a spinner row in sheets, scoped to what is loading — never a full-screen spinner.
- **Error:** a banner with the service's sentence and **Try again**; stale rows stay on screen when a refresh fails ("Couldn't refresh the list").
- **Pending design:** the row is muted and says "Waiting for agent"; its artboards say "screens/x.html isn't written yet" and fill in the moment the file is saved.
- **Narrow widths:** verified at 320 and 480 px with no horizontal scrolling.
- **Themes:** all colours come from the host theme tokens; a theme switch repaints live (checked light and dark).
- **Keyboard:** Tab reaches every control; arrow keys move inside menus and tabs; Escape closes menus, sheets and dialogs and returns focus to what opened them.
