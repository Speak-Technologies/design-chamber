# Design systems: the list, the New design system sheet and the system page

**Route:** the page's Library toolbar → **Design systems**, and the rail's header → **Design systems** (palette icon) · **Access:** every OpenChamber user
**Purpose:** See every design system in the Designs folder and make a new one. A design system is a set of colours, type, spacing and components, with notes on how to use them, that the chat agent reads before it designs. What a system is, how it is made and what the service enforces: [Design systems](../features/design-systems.md). A row opens the system's own page, described under [The system page](#the-system-page).

Screenshots come from `test/ui/visual/scenarios/design-systems-list.mjs` (the real UI with the in-memory fake service), in `documentation/pages/img/systems-<surface>-<width>-<theme>-*.png`.

## The list

[Rail 320 dark](img/systems-rail-320-dark-1-list.png) · [Rail 480 light](img/systems-rail-480-light-1-list.png) · [Page 1400 light](img/systems-page-1400-light-1-list.png)

- **Header.** The rail has a back arrow ("Back to designs"), the title, and under it **New design system** and **Build with the agent…**. The page has **Library** (back), the title, and both buttons on the right. New design system is the tinted button, **Build with the agent…** is an outline button (see [Build with the agent…](#build-with-the-agent)); the one filled button in the sheet is **Make design system**. Back returns focus to the Design systems button that opened the list.
- **A row** (a card on the page, where the list is a grid of cards three across at 1400 px):
  1. The name (one line, ends in an ellipsis) and its status: **Draft** or **Ready**.
  2. The home line: **In Design Chamber** or **Repo · shop** (the full path of the repo is the tooltip), then at most two badges, in this order of priority: **Being built**, **Changes to review**, **Default**, **Pinned for shop** (or "Pinned for 3 projects"), then the living page: **Living page out of date**, **Living page changed**, **Living page can’t be checked**. A third badge or more folds into **+1** (or +2…): its tooltip names what is folded, and the row's accessible name lists everything, so nothing is lost for a screen reader.
  3. When another system reads the same repo: "shop already has a repo-backed system (Acme)." in muted text. It is never a badge.
  4. A muted line: how complete the system means to be when it says so (**Tokens only**, **Core system** or **Full system**, first; nothing for a system that doesn't say), what it was made from ("From shop", "From brand files", "Described", joined with dots), who uses it ("Used by 4 designs", or "Not used by a design yet") and when it last changed ("2 hr. ago").
- **Row menu** (the ⋯ that appears on hover or focus): **Open**, **Make default** (or **Remove as default** on the default), **Reveal in folder**, **Rename**, **Delete…**. A draft can't be the default, so **Make default** is off and says "Mark it ready first." inside the menu.
  - **Rename** is a small dialog. A name is 1 to 60 characters and unique ignoring case: "You already have a system called Harbor." shows under the field as you type, and the service's sentence shows there too if it refuses.
  - **Delete…** confirms, because it is a deletion: "Delete Harbor? It moves to the trash. The 4 designs that use it keep their copy." After it, a toast says what else it cleared ("It was your default, so new designs ask again.").
  - **Make default** and **Remove as default** act at once and say what happened in a toast; the row shows **Default** once the service confirms.
- **Continue in chat** and **Pin to project…** are not in the menu yet; they arrive with the system page and with Settings.
- **The cap.** At 50 systems **New design system** is held back and the list says why ("You have 50 design systems, the most Design Chamber keeps. Delete one to make room.").

## States

- **A system that can’t be read:** the row shows the service's sentence in the error tone ("Design Chamber can’t read this design system. Its system.json isn’t valid JSON.") and a **Can’t read** badge. It is not a button (there is nothing to open); its menu keeps **Reveal in folder** and **Delete…**. [Rail 320 dark](img/systems-rail-320-dark-4-unreadable.png)

- **A refresh that failed** while rows are showing keeps the rows and adds "Couldn’t refresh the list" with **Try again**.
- The list refreshes by itself when the agent writes a file in a system or a system is added or removed, and the times age while it is open.

## Build with the agent…

[Rail 320 dark, the popover](img/build-popover-rail-320-dark-2-popover.png) · [Rail 320 dark, not sent](img/build-popover-rail-320-dark-3-not-sent.png) · [Page 1400 light](img/build-popover-page-1400-light-2-popover.png)

An outline button next to **New design system**, in the header of the list. It is there when the list is empty too (the three starts stay). At 50 systems it is held back with the same reason as New design system.

- **The popover.** An optional line, "What is it for? (optional)", up to 2000 characters ("Keep it under 2000 characters." under the field past that); **Agent works in** with **This chat** and **New chat**; **Cancel** and **Start**.
- **Which chat.** With a project folder open both are offered and This chat comes first. With no project folder only This chat is offered. With no chat open, This chat says "No chat is open right now. Open one first." and **Start** is off until **New chat** is picked.
- **Start** asks the agent to interview the user in that chat and closes the popover with a toast ("Asked the agent to build a design system. Answer its questions in the chat.").
- **When the request doesn't reach a chat.** The words stay. The popover says "Couldn’t ask the agent. The request didn’t reach a chat. Your words are still here." and **Start** becomes **Try again**; **Copy request** copies the text so it can be pasted into a chat by hand.

The chip the agent's request carries opens as described in [Rail: the build chip](rail.md#the-build-chip).

## The New design system sheet

[Page 1400 light, scanned](img/systems-sheet-page-1400-light-4-scanned.png) · [Rail 320 dark](img/systems-sheet-rail-320-dark-1-sheet.png)

Opened from **New design system** (a description is pre-ticked) or from an empty-list action (that source is pre-ticked). It makes an **internal** design system, kept in the Designs folder. A system that lives in a project's repo is made with the `/design-system` command in chat, not here.

1. **Name** (required). Filled in for you from the project when you read one and haven't typed anything.
2. **Start from**: three ticks, any mix, or none (a blank draft with only a name).
   - **Project code.** Choose a project (OpenChamber's projects by name, the current chat's project first) or **Other folder…** with a full path. It reads the project (nothing in it is changed), shows what it is doing and a **Cancel scan** button, then says what it found: "Found 48 colours, 9 type styles, 12 spacing values, 3 font files, 2 logo files in 14 files." plus an expandable **Files read** list, "Scanned part of the project; it’s large." when it hit a bound, the files it skipped, and the config files the agent will read because Design Chamber doesn't run them. Every font and logo found has a tick (ticked) to copy into the system, with "Check you’re allowed to use these fonts in designs." If it found nothing: "Design Chamber didn’t find design tokens in this project. The agent can still read it and write the system." A folder it can't read says why ("Pick your app’s folder, not the Designs folder.") and keeps what you typed. Starting a scan again is **Read ember-oak**.
   - **Brand files.** Drop files on the zone or **Choose files…**, or **Add from a folder…** (a full path; the service reads the files directly in it). Fonts (woff2, woff, ttf, otf, up to 5 MB), logos (svg, png, jpg, webp, up to 10 MB) and documents (pdf, md, txt, up to 20 MB), at most 400 files and 100 MB. Each file you pick shows its kind and size with a remove button; each one refused is named with its reason right away ("brand.key isn’t a file type design systems use.", "huge.woff2 is too large (the limit is 5 MB)."). [Rail 320 dark](img/systems-brand-rail-320-dark-1-files.png)
   - **A description.** Up to 2,000 characters and an optional **style preset**. A description or a preset is enough.
3. **Agent works in**: **New chat** (in the project you read, or the current one) or **Current chat** (attaches the system and puts the request in the composer).
4. **Make design system** (the one filled button). Nothing is written before it. Problems are shown **on press**, beside the thing to fix, and focus moves there: "Give the design system a name.", "Pick the project to read, or untick Project code.", "Add brand files, or untick Brand files.", "Describe the look you want, pick a style preset, or untick A description.". A failed make keeps the whole sheet and says "Couldn’t make the design system. <the service's sentence>".

While it works the form is locked and a line says where it is ("Making the design system…", "Adding brand files: 2 of 5, Mark.svg", "Asking the agent to write it…"). Files go one at a time after the system exists.

**When it all goes through,** the sheet closes with "Made Orchard. It’s a draft; the agent is writing it now." (or "…The request is waiting in the chat composer." for the current chat) and the new row is in the list.

**When something needs a look,** the sheet stays and becomes a result: "Orchard brand is made" with what is still open. [Page 1400 light](img/systems-brand-page-1400-light-2-result.png) · [Rail 480 light](img/systems-agent-rail-480-light-1-not-sent.png)
- **Files not added** lists each file with its sentence ("broken.png isn’t a real PNG file."). The rest are in.
- **Couldn’t ask the agent** (no chat, the host refused, the request wasn't built): the system is still a draft with what was gathered. **Try again** asks the agent again without making anything twice; **Copy request** puts the request on the clipboard when there is one.
- If the sheet was closed before the work finished, a toast says the same thing in one sentence.

## Keyboard and screen readers

Every control is reachable by keyboard with a visible focus ring. Rows are buttons whose accessible name lists the badges, folded ones too. Status is words and badges, never colour alone. Problems are in `role="alert"` lines; the scan line is a polite live region. Escape closes a sheet and stops a running scan.

## Rail and page

The same view on both. The rail (320 to 480 px) shows rows and the page shows cards in a grid. The sheet is a centred dialog on both and scrolls inside, with its buttons pinned.

## The system page

**Route:** a row (or **Open** in its row menu) in the list; a new system opens its page as soon as it is made · **Access:** every OpenChamber user. Screenshots come from `test/ui/visual/scenarios/design-system-page.mjs` in `documentation/pages/img/syspage-*.png` when that scenario is run with its default `--out`.

The sections below describe an **internal** system (kept in the Designs folder). A system that lives in a project's repo uses the same page, read only; see [A system that lives in a repo](#a-system-that-lives-in-a-repo).

### Full-screen page

- **Header.** Back (**Design systems**), the name (click to rename), a **Ready** or **Draft** badge, **Unsaved** while values are pending, and a line under it: "In Design Chamber · Core system · 3 topics left out · Synced with tidepool-web yesterday · Used by 4 designs". The depth the system was built to (**Tokens only**, **Core system** or **Full system**) and the count of topics the agent left out on purpose come right after where the system lives, so a narrow rail that cuts the line cuts the source first; the line wraps to three lines at most. Hover it for the topics by name ("Left out on purpose: Motion, Marketing."). A system written before depth existed shows neither, and its line reads as it always did. On the right: **Mark ready** (the one filled button while the system is a Draft) or **Back to draft** (outline, no primary when it is Ready), **Versions**, and a **⋯** menu (Rename, Continue in chat, **Re-sync from code** when the system has a code source, and **Export tokens…**; see [Export tokens](#export-tokens)).
- **Board.** The specimen board is drawn by the service and shown in a sandboxed frame (scripts on, never the page's own origin) on a quiet stage. It follows the OpenChamber light or dark theme. Clicking a swatch, a type sample or a component selects that entry in the panel and puts its name in the ask bar. While a value is pending the board shows it live. Component cards flow in columns at least 600 px wide: two when the board is about 1300 px wide or more (a full-screen page), one below that, so each card is as tall as its own preview and text, never stretched to match a neighbour. A card is one bounded group: the preview ground (a light one, plus a dark one stacked under it when the system has dark values) and the name, notes, variants, states and tokens sit together on a card that stands clear of the board in both themes. A preview wider than its column (a wide table, the desktop top bar) makes its card span the full board width; only a preview wider than the whole board scrolls, inside its own white or dark ground. That is the default layout (**card**); the agent can pick another per entry or per section in `system.json`, and the board follows it in the agent's order ([Board layout hints](../features/design-systems.md#board-layout-hints)): **compact** packs small pieces such as buttons and pills into narrow columns (about 280 px), **full** gives each entry the whole board width, one per row, and **table** lists entries as aligned rows (name, preview, notes; for tokens sample, token, note, the token column only as wide as its names; for text entries title, guidance and a note column only when an entry has a note), which stack one cell under the other when the section is under 760 px wide. Neighbouring entries with the same layout share a group, and groups stand 16 px apart. A board with no hints looks as before. A pattern or brand entry with a live example shows it like a component's, under its note, and a wide one takes the whole row. **Motion**, under Foundations after Shadows, shows each duration as a bar against the longest one and each easing as its curve, with a track under it that plays the token while hovered or focused (it stays still with reduced motion on). The board sits under the page's click layer, so the page tells the board where the pointer is and the board plays the track under it; a click on the track still selects the motion entry. At the top of **Assets**, an **Icons** grid shows each icon at the system's icon sizes on a light and a dark ground; an icon drawn only with `currentColor` takes each ground's text colour ([Motion](../features/design-systems.md#motion), [Icons](../features/design-systems.md#icons)). Under Colours, a **Pairs** block shows "Aa Text" in each colour pair on the light ground (and the dark one when the system has dark values) with its contrast ratio, or "Measured by the check" when the board can't work it out; clicking a pair selects it like any entry ([Depth, live examples and colour pairs](../features/design-systems.md#depth-live-examples-and-colour-pairs)). The overview, notes, patterns and brand bodies are markdown: the service renders their headings, paragraphs, bold and italic, strikethrough, inline code, code blocks, lists (nested too, ordered lists from their first number), links, tables, quotes and horizontal rules as formatted text. Every stretch of agent text is escaped and raw HTML in a note is shown as words, never markup; a link only carries an http, https, mailto or relative address. Tables render up to 64 columns and only as many rows as the note's own characters budget; a wider header, or rows past that budget, show as plain text instead of multiplying the page. A note whose body opens with its own title as a heading shows that heading once, as the card's label. The living page renders the same markdown in its own narrower vocabulary (code blocks as pre-wrap text, quotes as plain blocks, strikethrough as a span, headings to h4, ordered lists without a start number, and a link that leaves the page shown as its words and address), so it stays inside the allowlist the page is scanned against. Rendering is linear in the note's length: a hostile 20 000-character note cannot stall the service. Inside every layout (card, compact, full and table rows) the bodies render the same way, and their text stops at about 90 characters a line.
- **Panel (360 px).** "Sections" with "N of M reviewed" and a thin bar, then four areas that fold open: **Foundations** (Overview, Colours, Typography, Spacing, Radius, Shadows, Motion, Layers, Sizes), **Components**, **Patterns & voice**, **Brand & marketing**. Each section row shows its count ("8 colours", "Nothing yet") and, once reviewed, **Looks good** or **Needs work**. An area the system doesn't cover says "Not covered".
- **The section on show** lists its entries with a swatch, the light and dark value, and a usage note per token, style or component. **Click a value to edit it.** A value that is a formula (`var(--brand)`) is shown but locked, with the reason. Overview and note text shows here as the raw markdown with its line breaks kept (headings and lists on their own lines, not one collapsed paragraph); the board beside it shows the same text rendered.
- **What the panel adds for depth** (screenshots from `design-system-depth.mjs`: [pairs, dark](img/sysdepth-core-page-1400-dark-3-pairs.png), [sizes, light](img/sysdepth-core-page-1400-light-4-sizes.png), [scope, light](img/sysdepth-core-page-1400-light-2-overview.png), [the rail's header line, 320 dark](img/sysdepth-core-rail-320-dark-1-open.png); none of it shows on a system written before these fields, which reads exactly as before):
  - **Colours** ends with a **Pairs** group, one row per colour pair, in the order the service lists them. A row has the pair ("--text on --surface"), what it is for and the level it needs ("Body text, needs 4.5:1", "Large text, needs 3:1", "Interface part, needs 3:1"), then a light and, when the system has dark values, a dark ground, each with an "Aa" sample in the pair's own colours and the contrast ratio ("15.14:1"). A ratio under the level says **Too low** in words beside it, and a screen reader hears "Dark, 1.50:1, under 3:1". When the panel can't work the ratio out (a formula, or a colour such as `oklch()` it can't parse) the row says "Measured by the check", the same words the board uses, and a value it can't draw leaves a hatched sample. A pair the service found from the token names (`--accent-fg` on `--accent`) says "Found from the token names". A pair note shows under the row. Clicking a pair on the board selects its row.
  - **Components** list **Sizes** between **Variants** and **States**, only for a component that has some.
  - **Patterns & voice** and **Brand & marketing** rows name their kind in words: Layout, Do and don’t, Voice, Navigation, Overlays, Forms, Data display, Feedback, Empty, loading and error, Page template, Responsive, Motion, Accessibility, and for brand Marketing, Imagery, Logo use, Brand colour, Social, Email, Other. A kind this build doesn't know reads as plain words, never a raw id.
  - **Motion** lists its tokens like other token rows. Each says **Duration** or **Easing** beside its name, and its single value is labelled **Value** (a token with a dark value keeps **Light** and **Dark**). Values are edited in place like any other; a formula says neither and stays locked. The section row counts them ("2 durations, 2 easings", or "5 motion values" when one is a formula). With none: "No motion tokens yet. Ask the agent to add some."
  - **Assets** has an **Icons** group, then **Fonts and source files**. An icon row shows the picture, the name, the file and the note; the section row counts icons apart from files ("5 icons, 1 file"). With none: "No icons yet. Ask the agent to add some." The pictures come out of the specimen board and are only ever shown as `<img>`, so nothing inside an icon file runs. They sit on a pale tile in both themes, so black and `currentColor` icons stay visible (a white icon is best judged on the board's dark ground). An icon the board doesn't draw (a file over 32 KB, or one that can't be read) says "No picture. The file may be too large or unreadable." If the board can't load, the names still list under "The icon pictures didn't load." with **Try again**. Screenshots from `design-system-depth.mjs`: [motion, light](img/sysdepth-motion-page-1400-light-1-motion.png), [icons, dark](img/sysdepth-motion-page-1400-dark-2-icons.png).
  - **Overview** ends with a **Scope** block: the depth with one sentence on what it covers, and **Left out on purpose** with each topic by name (Motion, Marketing, Data display…). Neither part draws when empty. The rail has no section detail, so it carries only the header line's depth and count.
- **Editing.** A change goes into a pending list and the board previews it. An **Unsaved** bar appears with the count, **Reset** and **Save**. Save writes one edit; the service keeps a version first. After it: "Saved · Changed 1 value" with **Undo**. If the agent changed the files meanwhile the save is refused: "Tidepool changed while you were editing. Nothing was saved." with **Reload and try again**, and your typed values stay. Leaving the page with unsaved values asks: Keep editing, Discard, or Save and leave. A multiline value (overview, notes) opens in a textarea that keeps the line breaks, and Save writes them back as typed.
- **Review.** Under the panel: "Does Colours look right?" with **Looks good** and **Needs work**. A reviewed section shows its state once and only offers the other button. **Needs work** asks what to fix and sends it, with the section, to the agent. Sections the system doesn't cover say "Not covered by this system." and have no review controls. Review state lives only in this panel.
- **Mark ready.** "Acme is ready. 9 sections weren’t reviewed." with **Review the 9**, which jumps to the first section not reviewed. It never blocks.
- **Versions** opens a drawer from the right: the system's versions with **View**, **Compare** (the list of changed files) and **Restore**. Viewing an old version puts a banner on the page ("You’re viewing an old version.", **Back to current**) and turns editing off. A restore offers **Undo**, not a confirm.
- **Re-sync from code** opens a sheet that reads the project again and lets you tick what to take. It is written up in [design system re-sync](../features/design-system-resync.md) (screenshots `resync-page-*.png`, from `design-system-resync.mjs`). The rail never offers it.
- **Ask bar** under the board: it starts or continues the system's chat. With a board entry selected it sends the question about that entry. It says where the message goes ("Starts a new chat", or the linked chat's name).
- **Build strip.** When the agent is writing the system, a strip over the board says what it is doing, with **Stop** and **Undo**. When the **Board / Screens** switch is on show, the strip sits beside it in the same row instead, and drops to a line of its own when the rail is too narrow for both, so it never covers the switch.
- **Screens.** A system with screens (`system.json` `screens`, page templates, patterns, states and marketing pieces as full pages) gets a **Board / Screens (4)** switch over the stage. **Screens** shows every screen at each of its sizes on a small wall: the system's own sizes (Laptop 1280×800 and Phone 390×844 unless `system.json` `viewports` says otherwise), or a screen's own fixed sizes, such as a 1200×630 social card. Each size is the same sandboxed frame a design screen uses (scripts on, never the page's own origin) and takes the OpenChamber light or dark theme, so a screen's own `prefers-color-scheme: dark` values show in dark. Screens flow into lines that suit the stage's shape, each labelled with its name and size. Drag or scroll to pan, Ctrl or Cmd with the wheel to zoom, and the bar has zoom out, the zoom level (back to 100%), zoom in and **Fit**. Only the screens near the middle of the view are loaded (up to 12 on the page, 4 in the rail); the rest say "Paused" until you pan to them. A screen the system can't read (its file is missing or too long) keeps its place and says "This screen can’t be shown" with the reason and "Ask the agent to fix it." A screen that fails to draw says "This screen didn’t load" with the reason and **Try again**; one the system no longer lists says "That screen isn’t in this system any more." When the agent changes the files, restores a version or the theme changes, the loaded screens draw again; viewing an old version shows its screens. A system without screens shows no switch. While the agent is halfway through writing `system.json` and it can't be read, the switch and the wall keep the last screens that could be read, under the page's "can't be read" banner, and draw again once it reads (a system that has never been readable says "This system can’t be read right now, so its screens can’t be shown."). If the agent removes the last screen while Screens is open, it says "No screens yet. Ask the agent to add page templates." with **Back to the board**. Screenshots from `system-screens.mjs`: [page, light](img/sysscreens-page-1400-light-2-wall.png), [page, dark](img/sysscreens-page-1400-dark-2-wall.png).

### Rail panel

The same system, stacked and without value editing (the rail is too narrow for it): the board on top, the section list, the review controls, then **Back to draft / Mark ready** and **Continue in chat**, and a hint to open Design Chamber full screen to edit values. A repo-backed system shows the quiet "lives in" line, a living-page state label and **Preview living page**, and nothing else from the repo page. With screens, the same **Board / Screens** switch sits over the board; **Screens** is a list (name, then kind and sizes, or the reason a screen can't be shown) and the stage grows to two thirds of the rail. A row shows that one screen at its sizes, its name on a line of its own above the zoom controls, with **All screens** to go back (Escape too); focus returns to the row you opened. The rail can't open the full-screen page itself, so the list ends with how to get there for every screen side by side. The rail's view is written up in [rail: a design system](rail.md).

### Export tokens

**⋯ → Export tokens…**, on the full-screen page and in the rail, for internal and repo-backed systems. It saves the system's tokens as one ZIP; what is in it is in [Token export](../features/design-systems.md#token-export). Three steps: **⋯**, **Export tokens…**, **Export ZIP**.

- **The sheet** says "Saves Tidepool as one ZIP file in your export folder, Downloads unless you changed it. Your project isn’t changed." and ticks every format the system can export: **Design tokens (W3C)** (`tokens.json`), **CSS variables** (`tokens.css`) and, only when the project uses Tailwind, **Tailwind theme** (`tailwind-theme.css`). Untick what you don't want.
- **After it,** the sheet closes, a toast says "Saved to …" with the full path, and the page shows **Export saved** with the path and **Show in folder** for 15 seconds (longer while the pointer or focus is on it). When names had to be changed to keep them apart in `tokens.json` it adds "2 names were changed so they don’t clash in tokens.json. README.txt in the ZIP lists them."
- **States:** "Checking the formats…" while the service is asked; "Couldn’t check the formats. …" with **Try again**; **Export ZIP** reads **Exporting…** with both buttons off while the file is written; "Couldn’t export. …" with the service's sentence and **Try again**, ticks kept; "Pick at least one format." when none is ticked; a system with no tokens says "This design system has no tokens to export yet. Ask the agent to add some." with **Close**. If the sheet is closed while the file is being written, the result is still reported.
- **Off, with the reason in the menu,** while you view an old version ("Go back to the current version first."), have unsaved values ("Save or discard your changes first.") or the system can't be read.
- **Not on a phone.** The file is written on the computer that runs Design Chamber, so the menu leaves the entry out when the host says the device is a phone.

Screenshots and checks: `test/ui/visual/scenarios/system-export.mjs`. Code: `src/ui/systems/export-sheet.ts`, `src/ui/model/token-export-model.ts`.

### Comments on the board

Pins on the board, as on a design's wall, for notes to the agent about one entry: a swatch, a type style, a component, a pair. A comment is tied to the entry, not to a spot, so it stays on it when the agent draws the board again, when the theme switches and after a reload. How comments are kept and sent is in [Board comments](../features/design-systems.md#board-comments). Screenshots and checks: `test/ui/visual/scenarios/system-comments.mjs`.

- **Comment.** A **Comment** button sits at the top right of the board. Turned on it reads **Done**, a hint beside it says "Click an entry to comment on it. Esc to stop.", and a click on an entry opens a small card next to it: "Comment on component", the entry's name, a text box, **Cancel** and **Add comment** (Ctrl+Enter or ⌘Enter adds it too). A click on a spot that isn't an entry says so in the hint. Steps to add one: 3 (**Comment**, the entry, **Add comment**).
- **Pins.** Each comment is a numbered pin on its entry's top right corner, numbered in the order they were made; several on one entry sit side by side. An open comment is a filled pin, a sent one an outlined pin, a resolved one a check. A pin scrolled out of the board's view hides until it is back.
- **A pin's card** shows the number, the state (Open, Sent to chat, Resolved), the entry and the text to change, with **Delete**, **Resolve** (or **Reopen**), **Send this** for an open comment, and **Save** once the text changed. Delete asks once more on the button itself ("Delete comment?") because it can't be undone.
- **The list** sits at the top of the side panel: **Comments** with "2 open · 1 sent", then each comment with its entry, text, a send button (open ones) and resolve. Open comments come first, then sent ones; resolved ones wait behind **Show 1 resolved**. Pressing a row brings the board forward, scrolls it to the entry and opens the pin's card. Under the head, **Comment on** lists every entry of the section chosen in the panel (searchable, the selected entry first in line) and **Write comment** opens the card on it, so the keyboard reaches any entry, not only the first.
- **Send comments (2)** sends every open comment to the system's chat as one message; a row's send button or **Send this** sends one. After it the comments read **Sent** and a toast says "2 comments sent to the chat." (or "Started a new chat with comment 4." when the system had no chat yet; "3 of 5 comments sent. Send again for the rest." when they didn't all fit). The button says why it is off: no open comments, or an old version on show.
- **An entry that's gone.** A comment whose entry the agent removed is listed as "On an entry that’s gone", never drawn, and can still be opened, sent, resolved or deleted.
- **Words are never lost.** Text typed into a card and not added or saved is kept while Design Chamber is open: Escape, the close button, another entry or leaving the page keeps it, and the same card shows it again. Only **Cancel**, adding, saving, sending or deleting throws it away. A failed add or save keeps the text in the card with the reason.
- **States:** "Loading comments…"; "Comments didn’t load" with the service's sentence and **Try again**; "No comments yet. Turn on Comment and click an entry on the board to pin a note to it."; while sending, the button spins and the rows' send buttons are off; a failed send says "Couldn’t send. … Your comments are still here." and marks nothing; a damaged comments file shows "Some comments couldn’t be read" over the comments that could be, outside the folding part so it shows even when the list is folded; with none readable the head says "File damaged" and the banner says the next comment starts a new file. While you view an old version, **Comment** is off with the reason as its tooltip, the pins hide and nothing can be sent; the list stays.
- **Keyboard:** Tab reaches **Comment**, then the pins in number order; Enter opens a pin's card with focus in its text; Escape closes the card (keeping the words) and puts focus back on the pin (or its row when the pin is scrolled out of view); Escape again leaves comment mode. Escape closes an open card even when focus has left it. After **Save**, **Resolve**, **Reopen** or **Send this** focus stays in the card; after **Add comment** it goes to the new pin; after **Delete** to the next comment's pin or row. A pin's name is "Comment 1 on Button: The primary button reads heavy… (open)".
- **Rail.** The same pins and **Comment** button on the rail's shorter board. The card can't fit on it, so it opens at the top of the list, right under the board, while a marker stays on the entry; the rows step aside while it is open, and the list takes the room it needs (the sections wait under it). The hint is a line under the list's head instead of a pill on the board.

### Keyboard and screen readers

## A system that lives in a repo

The same page and the same panel, read only. The values live in the project's repo, so Design Chamber shows them and never writes them. Screenshots come from `test/ui/visual/scenarios/design-system-repo.mjs` (page, living-page card states, banners, preview frame, re-sync sheet) and `design-system-rail.mjs` (rail 320 and 480).

- **Header.** The name with its rename pencil and badge, then "Repo · shop · design-system/" (the full path is the tooltip). Right side: **Mark ready**, **Reveal** (shows the repo folder in the file manager), **Versions**, **⋯**. **Re-sync from shop** and **Export tokens…** are in the **⋯** menu.
- **Read-only line.** The first line of the panel, above the areas: "Acme lives in shop. Change the values there, or ask the agent here." It is a plain line, never a banner. There is no Save, Reset, Add, edit pencil or remove button, and no "Click a value to edit it." hint.
- **Review stays.** **Looks good** and **Needs work** work as before. **Needs work** and the ask bar send a proposal request to the system's chat, where the agent shows a diff for you to approve.
- **Coverage.** An area the system doesn't cover reads "Not covered by this system." and has no review buttons.
- **Living page card.** At the top of Overview, with the same state as a pill in the header. States: **Up to date** (Preview living page), **Out of date**, **Not in shop yet**, **Changed in shop**, **Reformatted**, **Can’t check as safe**, **Can’t read** (Reveal living page), and a build problem (**Ask the agent to fix it**). A token shaped like a secret on a page for developers adds a warning line. A font that was left out is named with the reason. **Embed fonts** is a switch on the card, and is not shown on a page for developers. After a change it says "Regenerating…" until the service reports the page again.
- **Preview living page** opens the staged page in a frame over the board (sandboxed, scripts on, never the page's own origin), with a note that the copy in the repo may differ. While a proposal waits, the frame shows the proposal's page and the band says so. The committed page is never drawn.
- **Banners.** At most two show, the rest fold under **+N more**. They cover: the repo can't be read (**Choose another folder…** opens the re-sync sheet), the snapshot was changed outside Design Chamber (**Re-sync**), changes since marked ready, and a build problem. Code that differs from the system and what a commit landed are plain lines in Overview with their own buttons (**Ask the agent to reconcile**), not banners. A count of zero with a file that couldn't be read never says "matches".
- **Versions.** **View** and **Compare** only. The footer says "Repo changes are undone in shop’s history, not here." A repo re-sync has no **Undo** notice for the same reason.
- **Re-sync sheet.** Lists what changed in the repo (**Changed**, **New**, **No longer in the repo**, **Files**) with the old and new value on one line. It is all or nothing, with **Apply** pinned in the footer. When nothing changed it says shop matches what Design Chamber shows and offers **Close**. When the repo can't be read it asks for the folder. Apply sends the scan and a stamp of the snapshot, never a value.
- **Being built in chat.** While the agent builds the system and there is no snapshot yet, the page says so, says when the agent is waiting for an answer, and offers **Continue in chat**, **Re-sync** and **Preview living page**.
