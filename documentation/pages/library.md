# Library: projects and folders

**Route:** OpenChamber sidebar → Extension pages → Design Chamber (`page` surface), the designs list before a design is opened · **Access:** every OpenChamber user
**Purpose:** Find a design among many. The library groups the same list two ways, and neither moves anything on disk: **projects** (automatic, from the project folder each design was made for) and **folders** (your own labels; one design can be in several). The rest of the library (cards, search, tabs, sort, New, Settings) is described in the [full-screen page](full-screen-page.md). The rail has the same groups in one select: see [Rail: projects and folders](rail.md). How the folders are stored is in [Projects and folders](../features/projects-and-folders.md).

Screenshots come from `test/ui/visual/scenarios/projects-folders.mjs`, `folder-picker.mjs` and `folder-manage.mjs` (the real UI with the in-memory fake service), in `documentation/pages/img/folders-page-<width>-<theme>-*.png`, `folder-picker-*.png` and `folder-manage-*.png`.

## The sidebar

[1400 light](img/folders-page-1400-light-1-library.png) · [1400 dark](img/folders-page-1400-dark-1-library.png)

- **All designs** (count), then **Projects**: one row per project folder that has designs (name, count, the full path as a tooltip), then **No project** (only when there are some), then **Folders** with **New folder** and one row per folder (name, count). A folder row's ⋯ menu holds **Rename**, **New folder…** and **Delete folder**.
- The selected row filters the grid and says so three ways: a bar and bold text on the row, `aria-current` for screen readers, and the page title ("Designs / shop"). Search, the tabs and sort work inside it, and the tab counts follow it. Cards show their project under the title, except inside that project.
- A project is named by OpenChamber's project list, else by the folder's name. Two projects with the same name show their parent folder too ("app · work", "app · personal"). A project folder that no longer exists still groups its designs, with a warning mark and "Folder not found" in the tooltip. Designs made from a chat opened in the Designs folder itself count as No project.
- The sidebar button in the toolbar opens and closes it. Under 900 px of page width it starts closed and floats over the grid when open ([800 px, open](img/folders-page-800-light-2-open.png)); choosing a row or pressing Escape closes it, and Escape returns focus to the button.

## Folders

- **New folder** opens a name field in the sidebar ([error](img/folders-page-1400-light-3-new-folder-error.png)). A name is 1 to 40 characters, with no line breaks or tabs, and unique ignoring case; at most 50 folders. The fix shows under the field and the text stays: "Give the folder a name.", "Keep the folder name to 40 characters or fewer.", "You already have a folder called Q4 launch.". Enter saves, Escape cancels. A folder row's ⋯ menu also offers **New folder…**, which opens the same field as a small dialog with **Create folder**.
- **Add a design:** drag a card onto a folder row (the row outlines as a drop target), or open the card's ⋯ menu → **Add to folder…** ([dialog](img/folder-picker-page-1400-dark-1-default.png), [light](img/folder-picker-page-1400-light-1-default.png)). The dialog lists **Projects** first, then **Folders**: the project the design was made for is ticked and locked ("Automatic. This design was made there."), a project you filed it under by hand reads "Added by you. Nothing on disk moved.", and every other row is a free tick. Ticking saves at once; a refusal shows its sentence under the list and the tick goes back. Past eight targets a search field appears ("Search folders and projects"). **New folder…** opens a name field with **Create and add**, and a status line says "Added to Q4 launch." afterwards. Drag is not the only way, so nothing needs a pointer drag. A toast says what happened on a drop, including "already in Q4 launch".
- **File a new design:** the New dialog has a **Folder or project** field under Design system ([rail 480](img/folder-picker-rail-480-light-2-new-field.png)): the same picker inline, the picks as removable chips (the chat's project is a fixed chip), and a line that says where the design goes ("Goes into Q4 launch. It also lands in ember-oak on its own. You can change this later."). It is optional and never blocks Start: if a target refuses, the design is still made and a warning notice names the folder and the reason with **Try again** ([notice](img/folder-picker-filing-1400-dark-1-failure.png)); the retry files just that target.
- **Inside a folder** the card menu also offers **Move to folder…** and **Remove from Q4 launch** ([menu](img/folders-page-1400-dark-5-folder-menu.png)); removing leaves the design in All designs and in its project. **Move** ([dialog](img/folder-manage-page-1400-dark-6-move-dialog.png)) is one pick: it untags the folder you are viewing and tags the target in one write, then a notice offers **Undo** for 10 seconds ([notice](img/folder-manage-page-1400-dark-7-move-undo.png)). A target that already holds the design is disabled with its reason; a refusal (a full or gone folder) shows its sentence in the dialog and changes nothing. The same entries appear for a design you filed under a project by hand; a design's own project can never be left.
- **Rename** is inline from the row's ⋯ menu. **Delete folder** asks first ([confirm](img/folder-manage-page-1400-dark-4-delete-confirm.png)): the confirm names how many designs are in the folder and how many of them are in no other folder ("2 designs are in Q4 launch. 1 of them is in no other folder; they stay in All designs."), with the promise "Deleting a folder never deletes designs." An empty folder reads "Scratch is empty. Deleting it changes nothing."; a folder whose designs all keep another folder reads "Its 6 designs all keep their other folders." After the delete, a notice reads "Deleted Q4 launch. Its 2 designs are still in All designs." with **Undo** for 10 seconds ([notice](img/folders-page-1400-light-7-deleted-undo.png)); the counts come from the delete itself, so a membership that changed meanwhile is reported truthfully. The clock stops while the pointer or focus is on it. While the folder is gone the view shows All designs, and Undo brings the folder and the view back.
- An empty folder says "No designs in Scratch yet. Drag designs here, or use Add to folder in a design’s menu." with **Show all designs** ([empty](img/folders-page-1400-light-6-empty-folder.png)).
- Deleting a design removes it from its folders at once.

## States

- **Loading:** two skeleton rows under Folders; the project rows and the grid load with the designs. The picker shows three skeleton rows in its Folders section until the list answers.
- **Empty:** first run shows All designs (0) and an empty Folders heading with a hint and **New folder**. The picker with no folders says "No folders yet. Name one below and this design goes in it." with the name field open and the projects still listed ([empty picker](img/folder-picker-page-1400-dark-6-empty.png)); with neither folders nor projects it shows the name field alone.
- **Error:** if the folder list can't be read, the sidebar keeps the projects and says "Folders couldn’t load. Try again." with **Try again** ([sidebar](img/folders-page-1400-dark-fail-1-sidebar.png)); designs still list. The picker says "Your folders didn't load" and "Projects still work. Check the service is allowed in Settings, then try again." with **Try again**, hides the create field and keeps the projects tickable ([picker error](img/folder-picker-page-1400-dark-5-error.png)). Failed saves keep what was typed and show the service's sentence next to the field.
- **No matches:** "No designs in shop match “hero”." with **Clear filters**.

## Remembered view

The chosen row is remembered on this surface (`list-scope:page` in `host.storage`). A stored value that is unknown, or names a project or folder that is gone, reads as All designs.
